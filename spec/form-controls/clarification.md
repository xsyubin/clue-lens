# 表单控件与交互体验体系化重构需求澄清清单 (clarification.md)

> 本文档轻量记录经需求方确认的业务口径与交互体验重构范围，作为后续技术需求细化与正式需求编写的唯一输入。  
> 最后确认时间：2026-11-10  
> 确认模式：用户已明确确认“均按推荐方案 A 执行”

## 一、背景与目标

- **目标用户**：专卖监管业务系统（ClueLens）所有前台操作人员（综合管理人员、线索核查执法人员、部门负责人、情报分析人员、专卖监督管理人员）及系统演示受众。
- **当前核心痛点**：
  1. **表单控件呈现原生粗糙感**：弹窗与工具栏内的下拉框直接采用原生 `<select>` 标签，依赖浏览器或操作系统原生样式，Mac/Windows 渲染割裂，点击后弹出操作系统原生纯白/纯灰浮层；
  2. **日期选择器视觉轴线断裂**：原生 `<input type="date">` 的日历小图标在 WebKit/Blink 内核下默认悬浮在正中间偏左，与上方 Select 的下拉箭头产生明显不对齐，且表单 Label 强加 `(YYYY-MM-DD)` 繁琐提示；
  3. **控件基建缺失导致各自为政**：`src/components/ui/` 缺少 `Select`、`DatePickerInput`、`Checkbox`、`Radio` 等基础表单组件规范，各业务组件直接内联编写原生标签与零散样式；
  4. **文本字符充当图标**：多个关键模态框（分派、复核、导入）直接用纯文本字符 `✕` 作为关闭按钮，字体渲染与垂直居中不协调。
- **预期价值**：
  在**不引入任何重型第三方组件库依赖、不破坏全栈极速构建性能与无障碍体验**的前提下，通过工程级轻量封装，全面提升表单与弹窗的视觉质感与交互一致性，使之完全达到现代专业中台标准。

## 二、已确认的范围边界

| 维度 | 已确认结论 |
| --- | --- |
| **技术策略** | **方案 A（轻量级现代封装）**：基于 Tailwind CSS v4 + React 19 + Lucide 矢量图标封装统一表单原子组件。使用 `appearance-none` 消除操作系统粗糙原生特征，所有右侧操作图标（`ChevronDown`、`Calendar`、`X`）统一贴靠最右侧（右边距 10px 处），保持绝对水平基准线垂直对齐。 |
| **范围内 (In-Scope)** | **全工程 100% 覆盖（9 个组件全包）**：<br>1. **基础组件基建扩充**：在 `src/components/ui/` 新增或强化 `Select`、`DatePickerInput`、`Checkbox`、`Radio`，支持统一高度（`h-9`）、统一圆角（`rounded-lg`）、统一 Focus Ring 焦点态与暗黑模式适配；<br>2. **全局日期样式重置**：在 `globals.css` 中重置 `::-webkit-calendar-picker-indicator` 默认行为，彻底消除图标居中悬空现象；<br>3. **分派弹窗改造**（`dispatch-dialog.tsx`）：部门人员下拉升级、日期框美化、去除 Label `(YYYY-MM-DD)`、复选框美化、关闭按钮换成 `<X className="w-4 h-4" />`；<br>4. **筛选工具栏改造**（`filter-bar.tsx`）：5 个原生 `<select>`（区域、类型、风险、状态、异常）全部替换为现代化 Select 组件；<br>5. **现场核查处置表单**（`handling-form.tsx`）：调查日期框升级为统一 DatePickerInput；<br>6. **复核裁决弹窗**（`review-dialog.tsx`）：单选 Radio 与关闭按钮 `✕` 升级；<br>7. **Excel 导入弹窗**（`import-modal.tsx`）：关闭按钮 `✕` 升级为矢量图标；<br>8. **工作台分页条**（`clues-workbench.tsx`）：每页条数选择器升级；<br>9. **角色切换器**（`role-switcher.tsx`）：切换下拉框升级；<br>10. **研判卡片**（`advisory-card.tsx`）：采纳复选框升级。 |
| **范围外 (Out-of-Scope)** | 1. 引入 `@radix-ui/react-select` 等沉重无头第三方库（避免引入几万行复杂 DOM 模拟与水合负担）；<br>2. 修改后端业务逻辑、数据库 Drizzle Schema 或 Server Actions 接口契约；<br>3. 重新设计整体页面排版布局。 |
| **零破坏保障** | 重构仅作用于视觉表现层与交互封装层，不改变任何表单字段的 `name`、`value`、`onChange` 或校验逻辑，现有自动化测试与业务流程 100% 保持兼容。 |

## 三、用户角色与交互契约

系统涉及的 5 类业务角色在操作各类表单时应获得完全一致的现代交互体验：

| 角色 | 涉及的核心表单与控件 | 重构后的交互契约标准 |
| --- | --- | --- |
| **综合管理人员** | • 分派线索弹窗（承办部门/人员/办理期限/是否复核）<br>• 台账导入弹窗（关闭与上传） | 1. 下拉框展示清晰的 `ChevronDown` 箭头；<br>2. 日期选择框日历图标固定靠右，点击整行或图标快速呼出日期选择器；<br>3. 弹窗右上角为标准的灰度渐变平滑关闭按钮。 |
| **线索核查人员** | • 现场核查与处置登记表单（调查日期、事实结论） | 日期输入框与文本域的边框、Focus 焦点光圈与圆角高度一致。 |
| **部门负责人** | • 办理结果终审复核弹窗（通过/驳回 Radio、复核说明） | 单选 Radio 拥有清晰的勾选动效与鲜明的颜色状态（通过为翡翠绿，驳回为警示红）。 |
| **全员/情报/监督** | • 工作台综合筛选栏（5个维度筛选）<br>• 分页条数切换器<br>• 顶部操作角色切换器 | 筛选栏所有下拉框视觉高度统一为 `h-9`，右侧小箭头统一靠右居中，深色模式下背景与文字高对比度无反差错乱。 |

## 四、已确认的设计规范与交互标准

1. **几何与对齐规范**：
   - 表单控件统一高度：标准尺寸 `h-9`（36px），紧凑尺寸 `h-8`（32px）。
   - 统一圆角：`rounded-lg`（8px），保持与整体卡片圆角协调。
   - 统一右侧图标定位：右侧内嵌图标距右边缘统一为 `pr-3` 或 `right-2.5`，形成垂直一条线的视觉对齐。
2. **状态规范**：
   - 默认态：边框 `border-slate-200 dark:border-slate-700`，背景 `bg-white dark:bg-slate-900`。
   - 焦点态：`focus:ring-2 focus:ring-emerald-500/20 focus:border-emerald-500 outline-none`。
   - 悬浮态：`hover:border-slate-300 dark:hover:border-slate-600`。
   - 禁用态：`opacity-50 cursor-not-allowed`。
3. **关闭按钮规范**：
   - 统一使用 `<button onClick={onClose} className="p-1 rounded-md text-slate-400 hover:text-slate-600 dark:hover:text-slate-200 hover:bg-slate-100 dark:hover:bg-slate-800 transition-colors"><X className="w-4 h-4" /></button>`。
