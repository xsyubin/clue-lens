# 专卖监管线索分析与闭环管理系统需求规格说明书

## 引言

本项目旨在通过 AI Coding 现场演示与工程实践，将分散在各部门中的 Excel 监管线索台账快速转化为开箱即用、具备业务闭环的“专卖监管线索分析与闭环管理小系统”。系统围绕“能导入、能查询、能分析、能流转、能闭环、能导出”的建设目标，实现脱敏台账文件上传解析、全景宏观大盘透视、多维异常特征自动识别、双模辅助处置建议生成、全生命周期分派核查与复核流转闭环，以及多形态研判报告导出，全面解决传统台账查询难、重发对象难发掘、流转脱节与统计繁重等痛点。

## 边界上下文

- **范围内**:
  1. 支持 `.xlsx`、`.xls`、`.csv` 格式脱敏线索台账上传解析与基于“线索编号”的 Upsert 增量入库；
  2. 提供全景宏观态势分析大盘（核心指标卡、高发类型 TOP N 榜、区域分布、趋势图表）；
  3. 提供多条件复合高级筛选与经营对象模糊检索；
  4. 内置规则引擎自动计算并打标 5 类监管异常（重复对象、区域集中、涉及金额异常、办理超期、高风险未分派）；
  5. 双模处置建议生成（离线专家规则秒级推荐 + 可选大模型智能润色）；
  6. 覆盖“待分派 $\rightarrow$ 办理中 $\rightarrow$ 待复核 $\rightarrow$ 已完成 $\rightarrow$ 已关闭”的 5 状态全生命周期闭环与驳回回退；
  7. 线索详情流转时间轴 (Timeline) 与全局安全审计留痕；
  8. Excel 多 Sheet 统计台账与 Markdown/网页打印研判报告初稿双形态导出；
  9. 顶部快捷切换演示角色模式（综合管理、核查人员、部门负责人、情报分析、监督管理）。
- **范围外**:
  1. 外部政务专卖专网数据库双向实时同步；
  2. 外部短彩信通知平台与呼叫中心 (CTI) 硬件直连；
  3. 现场音视频取证大附件存储、司法链存证与电子签章；
  4. 纸质卷宗图文 OCR 扫描识别；
  5. 复杂微服务架构与生产级消息队列削峰。
- **相邻预期**:
  系统完全采用单机自包含 SQLite 数据库及本地前端处理，以脱敏 Excel 文件作为唯一数据交换边界，100% 具备无网络依赖的离线闭环演示能力。

## 业务需求

### 需求 1: Excel 台账数据导入与解析 (Import & Ingestion)

**目标:** 作为综合管理人员，我希望上传脱敏 Excel 线索台账，从而将分散的线索快速统一入库并完成格式校验。

#### 验收标准
1. `When` 综合管理人员上传合法的 `.xlsx`、`.xls` 或 `.csv` 文件，`the 导入服务 shall` 自动解析并匹配表头字段，以“线索编号”作为唯一业务主键执行 Upsert 增量入库。
2. `If` 待导入的线索编号在系统中已存在，`then the 导入服务 shall` 更新该线索的最新属性字段，并保留该线索既有的历史流转记录与时间轴不被清除。
3. `If` 某行数据存在必填字段缺失（如缺少线索编号或发现日期）或类型格式错误，`then the 导入服务 shall` 跳过该错误行，并在导入结果面板中明确列出失败行号及错误原因。
4. `If` 上传的文件损坏、内容为空或无任何匹配的标准表头字段，`then the 导入服务 shall` 终止导入事务并返回阻断性错误提示，数据库现有数据保持原样。
5. `The 导入服务 shall` 在批量入库完成后，自动触发全库异常规则重新计算，并秒级刷新全景大盘统计卡片与线索列表。

---

### 需求 2: 多维筛选与全景态势大盘 (Dashboard & Multi-Filter)

**目标:** 作为情报分析人员与专卖监督人员，我希望多维度过滤与监控线索，从而快速洞察异常态势与重点区域。

#### 验收标准
1. `When` 用户在顶部或侧边筛选栏选择所属区域、发现时间范围、线索类型、风险等级、办理状态、责任部门或异常标签组合条件，`the 线索大盘 shall` 秒级联动过滤并刷新统计指标卡片与下方的线索列表。
2. `When` 用户在搜索框输入经营对象名称或线索编号关键字，`the 线索大盘 shall` 执行实时模糊匹配并呈现命中结果。
3. `While` 组合筛选条件下的匹配记录数为 0 时，`the 线索大盘 shall` 展示空数据状态插画并提供“一键重置筛选”操作按钮。
4. `The 线索大盘 shall` 实时统计并展示线索总数、高风险线索数、待办理线索数、已超期线索数，以及按线索类型分布的 TOP N 统计图表。

---

### 需求 3: 规则引擎自动异常识别 (Anomaly Detection)

**目标:** 作为情报分析人员，我希望系统自动标记高危特征，从而防止重点线索、超期事项或累犯主体被遗漏。

#### 验收标准
1. `When` 某一经营对象在系统全库中累计关联的线索记录数量 $\ge 2$ 条，`the 规则引擎 shall` 自动为该线索标记“重复出现对象”预警标签，并展示历史出现总次数。
2. `When` 某一所属区域在近 30 个自然日内新增的线索数量 $\ge 5$ 条，`the 规则引擎 shall` 自动为该区域的所有新线索标记“区域集中出现”警示标签。
3. `When` 某一区域在近 30 个自然日内同一线索类型累计数量 $\ge 3$ 条，`the 规则引擎 shall` 自动为对应线索标记“同类问题连发”警示标签。
4. `When` 线索涉及金额数值 $\ge 100,000$ 元，`the 规则引擎 shall` 自动为该线索标记“涉案金额异常”警示标签。
5. `While` 线索未处于“已完成”或“已关闭”状态，`when` 当前系统日期晚于该线索的“办理期限”，`the 规则引擎 shall` 自动标记“办理超期”红色警示标签。
6. `When` 线索的风险等级为“高”且当前办理状态为“待分派”，`the 规则引擎 shall` 自动标记“高风险未分派”警示标签。

---

### 需求 4: 双模辅助处置建议生成 (Disposal Advisory)

**目标:** 作为线索核查人员与情报分析人员，我希望获取智能处置建议，从而为现场排查与执法措施提供决策指引。

#### 验收标准
1. `When` 经办人员在线索详情页面点击“生成处置建议”按钮，`the 建议生成引擎 shall` 根据当前线索的“线索类型”（许可证/经营/配送/价格等）与“风险等级”（高/中/低）秒级匹配内置专家决策规则库，输出标准化处置建议方案。
2. `Where` 系统环境中配置了有效的大模型 API 密钥且用户勾选“AI 深度研判”，`the 建议生成引擎 shall` 发起智能分析请求，综合该经营对象历史线索、区域聚集特征生成定制化研判与深度处置措施。
3. `If` 大模型接口调用超时、网络故障或未配置密钥，`then the 建议生成引擎 shall` 自动无缝降级为内置专家建议模板输出，界面提示“已切换为专家规则推荐”，保障业务连续可用。
4. `When` 用户在建议面板中点击“采纳处置建议”，`the 建议生成引擎 shall` 将建议文本自动填入线索详情的“处置措施”编辑框，并允许经办人员再次人工修改完善。
5. `The 建议生成引擎 shall` 明确标注处置建议为辅助参考信息，未经核查人员显式提交确认，不直接作为正式结论持久化入库。

### 需求 5: 全生命周期分派与状态闭环流转 (Lifecycle Workflow)

**目标:** 作为不同职责岗位的经办人员，我希望协同推进线索办理，从而实现跨部门闭环流转与严格责任留痕。

#### 验收标准
1. `While` 线索处于“待分派”状态，`when` 综合管理人员选择责任部门、责任人、设定办理期限并勾选“是否需要复核”后提交，`the 流转服务 shall` 将该线索状态变更为“办理中”。
2. `If` 分派提交时办理期限早于当前系统日期，或未指定责任人，`then the 流转服务 shall` 拒绝分派请求并返回明确的表单校验错误信息。
3. `While` 线索处于“办理中”状态且“需要复核=否”，`when` 责任核查人员登记核查日期、核查结果与采取的处置措施并提交办结，`the 流转服务 shall` 将状态直接变更为“已完成”。
4. `While` 线索处于“办理中”状态且“需要复核=是”，`when` 责任核查人员登记核查日期、核查结果与处置措施并提交办结，`the 流转服务 shall` 将状态流转为“待复核”。
5. `While` 线索处于“待复核”状态，`when` 部门负责人审核并点击“复核通过”，`the 流转服务 shall` 将状态变更为“已完成”，并记录复核通过意见与复核时间。
6. `While` 线索处于“待复核”状态，`when` 部门负责人点击“复核驳回”并输入驳回意见，`the 流转服务 shall` 将线索状态退回至“办理中”，并将驳回意见同步追加至时间轴。
7. `If` 部门负责人执行复核驳回时未输入驳回意见，`then the 流转服务 shall` 阻止驳回提交并提示“驳回时必须录入驳回原因”。
8. `While` 线索处于“已完成”状态，`when` 部门负责人点击“归档关闭”，`the 流转服务 shall` 将状态流转为终态“已关闭”。
9. `The 流转服务 shall` 在每次分派、办结提交、复核通过、复核驳回及归档关闭时，在线索详情的时间轴（Timeline）中完整记录经办角色、操作类型、时间戳、前后状态与备注意见，并同步写入系统全局安全审计日志。

### 需求 6: 多形态分析报告与台账导出 (Report Export)

**目标:** 作为情报分析人员与部门负责人，我希望导出台账与报告，从而支撑周报月报汇报与线下归档。

#### 验收标准
1. `When` 用户在列表或大盘点击“导出 Excel 台账”，`the 导出服务 shall` 根据当前筛选条件生成包含“线索明细清单”与“区域/类型统计汇总”多 Sheet 的 `.xlsx` 文件并触发浏览器下载。
2. `When` 用户点击“导出研判分析报告初稿”，`the 导出服务 shall` 提取当前线索态势指标、重点高发区域、高危重复经营对象、超期清单及后续处置建议，生成格式规范的 Markdown 文档并触发下载。
3. `When` 用户点击“打印分析报告”，`the 导出服务 shall` 打开专用的无侧边栏打印排版视图，并调起浏览器系统打印对话框。

## 流程与状态需求

```text
[待分派 PENDING_ASSIGN]
       │
       ▼ (综合管理人员分派)
[办理中 IN_PROGRESS] ◄────────────────────┐
       │                                  │ (复核驳回，退回并留痕)
       ├──────────────┬───────────────────┤
       │ (需复核=否)  │ (需复核=是)        │
       │              ▼                   │
       │       [待复核 PENDING_REVIEW]────┘
       ▼              │ (复核通过)
[已完成 COMPLETED] ◄──┘
       │
       ▼ (部门负责人终审)
[已关闭 CLOSED]
```

| 当前状态 | 角色/动作 | 前置条件 | 目标状态 | 失败、撤回或驳回 | 关联需求 |
| --- | --- | --- | --- | --- | --- |
| **待分派** (`PENDING_ASSIGN`) | 综合管理人员执行“分派” | 已录入部门、责任人且办理期限有效 | **办理中** (`IN_PROGRESS`) | 校验未通过时停留在“待分派”并报错 | 需求 5 |
| **办理中** (`IN_PROGRESS`) | 核查人员执行“办结提交” | 已填报核查结果且“需要复核=否” | **已完成** (`COMPLETED`) | 必填项缺失阻止提交 | 需求 5 |
| **办理中** (`IN_PROGRESS`) | 核查人员执行“办结提交” | 已填报核查结果且“需要复核=是” | **待复核** (`PENDING_REVIEW`) | 必填项缺失阻止提交 | 需求 5 |
| **待复核** (`PENDING_REVIEW`) | 部门负责人执行“复核通过” | 无 | **已完成** (`COMPLETED`) | 审批失败保持“待复核” | 需求 5 |
| **待复核** (`PENDING_REVIEW`) | 部门负责人执行“复核驳回” | 必须输入驳回原因 | **办理中** (`IN_PROGRESS`) | 未填驳回原因阻止驳回，保持“待复核” | 需求 5 |
| **已完成** (`COMPLETED`) | 部门负责人执行“归档关闭” | 线索已结案 | **已关闭** (`CLOSED`) | 仅允许终态查看，不可逆向流转 | 需求 5 |

## 非功能需求

1. **响应性能**:
   - 本地 SQLite 在 10,000+ 条线索规模下，多维组合筛选响应时延 $\le 200\text{ms}$；
   - 1,000 行 Excel 数据解析校验与 Upsert 批量入库耗时 $\le 3\text{秒}$。
2. **离线高可用与安全性**:
   - 处置建议引擎具备 100% 离线规则保底，无外部 LLM 网络连接时仍可完整运行；
   - 严禁向客户端泄露未经脱敏的真实手机号或敏感涉案主体身份信息；
   - 服务端所有写操作强制进行参数防御校验（Zod safeParse）与角色鉴权防卫。
3. **数据完整性与审计**:
   - 线索生命周期的每一次状态跃迁与核心字段修改均必须在时间轴中永久留痕；
   - 系统记录全局安全审计日志表，包含操作人、操作角色、时间戳、IP、动作及变更摘要。

  4. 处置建议双模策略模式的具体类设计与接口实现。
